# Публикация и очистка

## Sites

`.openai/hosting.json` хранит логические привязки `DB` и `BUCKET` и ID сайта. Хостинг создаёт постоянные D1/R2 и применяет `drizzle/*.sql` перед загрузкой Worker. Секреты в исходниках отсутствуют. Для другой инсталляции зарегистрируйте новый Site и замените `project_id`; не используйте чужой ID.

1. `npm ci`, затем `npm run build`.
2. Проверить `dist/server/index.js`, `dist/client`, `dist/.openai/hosting.json` и миграции `dist/.openai/drizzle`.
3. Закоммитить и отправить точный исходный код в привязанный репозиторий Sites, используя временный токен только на один вызов Git.
4. Через Sites сохранить версию с SHA отправленного коммита и архивом сборки, затем опубликовать эту версию. Выбрать публичный доступ — ученикам не нужна учётная запись хостинга.
5. Подтвердить успешный конечный статус публикации и проверить публичный `/api/health`, создание комнаты и отчёт.

Новые SQL-миграции добавляются последовательно. Применённые миграции не редактировать. `dist/server/wrangler.json` содержит локальные привязки; не отправлять его напрямую в другой Cloudflare аккаунт без настройки реальных D1/R2.

## Автоматическое удаление

GitHub Actions `.github/workflows/cleanup.yml` вызывает `POST /api/cleanup` каждый час, на 17-й минуте. Нужен репозиторий с включёнными Actions и repository variable `TASKBATTLE_URL` — публичный HTTPS origin без завершающего пути. Персональные токены не нужны. После настройки обязательно запустить workflow вручную и проверить его успешность.

Этот endpoint намеренно не требует административного секрета: он не принимает идентификаторы/время/SQL от клиента и может удалять только уже истёкшие записи. Его общий лимит — один запуск в минуту. За запуск автоматически завершается до 500 просроченных попыток и удаляется до 500 файлов; workflow делает до 5 пакетов с паузами. Сначала просроченные попытки завершаются по deadline_at; только после истечения 72 часов результата они превращаются в минимальные записи истечения без ответов и фото. Файлы, которые не нужны ни открытой комнате, ни начатой попытке в пределах её 24 часов, ни отчёту с оставшимися 72 часами, атомарно помечаются deleting. Затем удаляются байты R2 и журнал, а комната удаляется только после освобождения всех ссылок. Повтор после сбоя безопасен. Прерванные загрузки очищаются через час. Активная комната и необходимые любому доступному отчёту файлы не удаляются. Миграция 0001 применяется после 0000, сохраняет существующие строки и заполняет сроки старых отчётов. Перед самостоятельным переносом сохраните резервную копию базы.

Ручная проверка: `curl -X POST https://YOUR_SITE/api/cleanup`. Ответ содержит deletedFiles, deletedAttempts и finalized; workflow продолжает пакеты, пока один из счётчиков достигает 500. В GitHub проверяйте историю `Delete expired TaskBattle data`. GitHub может задерживать scheduled workflows, а в публичных репозиториях выключать их после периода отсутствия активности. Если нужен SLA удаления, перенесите вызов в постоянно обслуживаемый внешний cron. Доступ к данным блокируется ровно по сроку независимо от задержек cron.

## Отсутствие платных подключений

Проект не подключает платёжные средства и не покупает тарифы. При переносе на другой хостинг владелец самостоятельно проверяет доступные квоты. Лимиты приложения ограничивают использование, но не заменяют квоты провайдера.
