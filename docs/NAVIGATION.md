# Свободное прохождение (timing_version=3)

## Состояние и совместимость

Номера и отображение всегда соответствуют `tasks.ordinal`. `selected_task_id` отвечает только за открываемую задачу, `position` в новой модели — число принятых ответов. Уникальная пара `(attempt_id, task_id)` хранит последнюю принятую редакцию; `revision` увеличивается при изменении. Автозавершение возможно только когда приняты ответы на все задачи.

`GET /attempts/:id/journey` один раз переводит активную старую попытку в новую модель. Существующие ответы превращаются в закрытые начальные интервалы. Текущая задача вычисляется внутри транзакции из актуального `order_json[position]`, без гонки с прежним клиентом. Исходные slot-позиции сохраняются для совместимости уникального индекса старых ответов. Готовые результаты не переписываются. После обновления старые запросы записи отвергаются, включая загрузки, начавшиеся до обновления. Текст/фото локального старого черновика переносятся по историческому slot и стабильному task ID.

## Интервалы

`attempt_intervals` хранит независимые посещения задач. Единственный `attempts.ready_id` указывает на активное посещение; `state_version` обеспечивает CAS при открытии. Владельцем является вкладка. Закрытый интервал неизменяем: первый запрос фиксирует миллисекунды, точный повтор ничего не добавляет, другой результат получает конфликт. Одновременные переходы не удваивают время.

Клиент фиксирует интервал до сети и сохраняет небольшой recovery-указатель. Сначала сервер подтверждает закрытие; затем происходят подготовка изображения, отправка или переход. Новый интервал начинается после загрузки условия и подтверждения открытия. Подготовка фото и сеть исключаются. Выбор снимка пользователем, обычный фон и блокировка экрана входят в активный интервал; фон не вызывает закрытие.

Каждые 5 секунд активная вкладка посылает монотонный checkpoint. При перехвате другой вкладкой или завершении по календарному дедлайну, если точный close утрачен, остаётся последний подтверждённый checkpoint и `timing_incomplete`. Неизвестное ожидание сети не превращается в часы решения. При обычном reload тот же интервал и локальная точка начала восстанавливаются без паузы и обнуления. При полном отказе локального хранилища восстановление после закрытия браузера ограничено; интерфейс предупреждает об этом.

Общее время — сумма всех закрытых интервалов всех задач, включая неотправленные. Среднее и экстремумы — по задачам с принятым ответом, с их полной накопленной длительностью, включая повторное редактирование. В отчёте при ручном завершении остаётся принятый ответ, даже если локальный черновик изменён. Время черновика при этом включается. Данные хранятся в миллисекундах; интерфейс показывает десятые секунды.

## Черновики и фотографии

Черновики ключуются `journey:attemptId:taskId`. Текст/метаданные и файл хранятся отдельно в IndexedDB, синхронное хранилище не содержит байтов фото. Отказ IndexedDB не блокирует отправку файла из памяти. Без работающего локального хранилища закрытие вкладки может потерять неотправленное фото — это явно показывается. Эти черновики не синхронизируются между устройствами; принятые ответы и интервалы находятся на сервере.

Предпросмотр использует объектные URL с освобождением. Неудачная замена оставляет прежнее фото. `photoAction` различает сохранение принятой фотографии, её замену и явное удаление. Каждая загруженная редакция имеет новый immutable R2 key; старый объект удаляется только когда на него больше не ссылается ответ. Неудачные и поздние загрузки удаляются через существующий журнал blobs и cron.

После неопределённого результата отправки перед редактированием записывается cancellation fence. Если ответ уже принят, snapshot возвращает эту редакцию. Если ещё загружается — поздняя запись запрещена. `attempt_operations` хранит request ID, хеш тела и токен применения: повтор старого запроса не откатывает более свежую редакцию. Photo upload, CAS ответа, операция и terminal transition защищены проверками server deadline и транзакцией D1.

Один браузерный экземпляр сериализует отправку/переход; быстрые нажатия номеров сохраняют последний желаемый номер. Во время отправки навигация временно блокируется. При конфликте другой вкладки остаются черновик и действия восстановления. Работающая вкладка не может дописать время в интервал, уже закрытый другой вкладкой.

## Маршруты

- `GET /api/attempts/:id/journey`: защищённый снимок, безопасное обновление активной старой попытки.
- `POST .../journey`: begin, arm, checkpoint, close, takeover, adopt-legacy, cancel, finish. Все требуют ключ попытки.
- `POST .../journey-answer`: multipart с текстом, request ID, task ID, revision, state version и photoAction. В API правильность скрыта до завершения.
- `POST .../export`: только преподаватель, только доступный завершённый результат. См. [Google Sheets](GOOGLE_SHEETS.md).

## Миграция

`0005_navigation_and_exports.sql` сгенерирована из `db/schema.ts`: добавляет год AMC, темы, ревизии, курсор, интервалы, журнал операций и экспорты. Не удаляет комнаты, результаты или файлы. Старые завершённые результаты сохраняют прежние правила вычисления. Очистка удаляет интервалы/операции/локальное соответствие экспорта каскадом с попыткой; внешние листы Google никогда не удаляются.
