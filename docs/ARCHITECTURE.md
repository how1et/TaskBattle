# TaskBattle: модель и безопасность

React / Vinext UI → Cloudflare Worker API → D1 и закрытый R2. Никакой регистрации и никакого клиентского ключа доступа к базе. Таблицы создаются миграциями Drizzle, никогда во время HTTP-запроса.

## Данные

- `rooms`: случайный 192-битный идентификатор + срок в base36, название, SHA-256 секрета преподавателя, request ID, срок ровно 172800000 мс, количество задач.
- `tasks`: неизменяемый исходный номер, ключ файла, MIME, правильный ответ.
- `attempts`: случайный UUID, SHA-256 отдельного секрета из 64 hex-символов, постоянный порядок загрузки для новых попыток; сохранённый прежний порядок для начатых, позиция, начало попытки/задачи, завершение.
- `answers`: оригинальная строка, результат проверки, отметки и длительность, уникальные `(attempt_id,position)` и `(attempt_id,request_id)`.
- `blobs`: журнал файлов и сроки удаления, включая прерванные загрузки.
- `rate_limits`: общие для экземпляров сервера счётчики с истечением.

## Доступ

Ссылка комнаты — capability: любой её обладатель может видеть фотографии и создавать попытки. Она не позволяет просматривать результаты других попыток. Учительский ключ хранится во фрагменте URL и передаётся в `x-teacher-key`, секрет попытки — в `x-attempt-key`. Фрагменты не включаются браузером в HTTP URL/Referer. На странице нет сторонних скриптов и аналитики; применяется `no-referrer`. HTTPS обязателен в production. Секретные ссылки нельзя публиковать.

Фото выдаёт только API после проверки существования комнаты, принадлежности задачи и срока. R2 не имеет публичных ссылок. API и фото получают `private, no-store`. Правильные ответы и промежуточная оценка исключены из ученического JSON явным списком разрешённых полей. Только завершённая попытка получает свой разбор. Учителю нужен отдельный ключ комнаты. Нет списка всех комнат.

Срок проверяется на сервере при каждом доступе, повторно перед выдачей снимка попытки и фотографии. Cron нужен для физического удаления, а не для запрета доступа. Время, закодированное в ID, используется только для понятного сообщения после удаления; пока запись существует, авторитетно поле D1. Скачанные ранее изображения или сохранённый человеком отчёт невозможно отозвать.

## Повторы и конкуренция

Идентификатор/секрет старта генерируются до запроса и сохраняются как клиентский указатель восстановления. Сервер хранит окончательные порядок и отметки; необязательный клиентский черновик содержит активный интервал. Повтор старта возвращает ту же попытку.

Ответ записывается через условный `INSERT ... SELECT` и `UPDATE` в одной транзакции D1 `batch`. Сверяются ожидаемая позиция и задача; уникальные индексы и проверка request ID ограничивают продвижение одной позицией. При одновременном повторе с иным ответом возвращается 409. Принятый ответ неизменяем; безопасный повтор возвращает исходный результат без изменения времени. Неудавшийся запрос вместе с файлом, ready ID, request ID и зафиксированным временем остаётся в IndexedDB как черновик; поле блокируется до подтверждения, чтобы повтор имел то же тело. Это не основное хранилище результатов.

Создание комнаты тоже использует request ID. Неизменённый повтор возвращает ту же комнату. Изменение формы после ошибки начинает новое создание. Загрузка файлов регистрируется в D1 до R2; оборванные загрузки удаляются через час. Ошибка, результат которой неизвестен, сначала сверяется с D1; нельзя вслепую удалять файлы потенциально созданной комнаты.

`GET /api/creations/:requestId` восстанавливает результат только по исходному `x-teacher-key`, проверяя его хеш и срок комнаты. Неверный/отсутствующий ключ возвращает 404. Это позволяет восстановить ответ без повторной передачи фотографий. После сетевой ошибки клиент проверяет сохранение и допускает один автоматический повтор загрузки с тем же request ID; проверка уже созданной комнаты выполняется до квоты новых созданий. Upload ограничен 120 секундами на запрос, recovery — 15 секундами, предварительная загрузка фото — 45 секундами. Timeout не означает отмену серверной транзакции. Незавершённый request ID/секрет сохраняются в sessionStorage для восстановления после обновления; фото формы там не хранятся. Журнал неожиданных ошибок содержит этап, случайный trace ID, длительность и имя класса ошибки без фото, ответов и секретов.

Для редактирования после неудачной отправки `/cancel-answer` атомарно помечает прежний request ID в `cancelled_answers`. Условная запись ответа проверяет эту отметку в той же транзакции. Если сохранение выиграло гонку, возвращается уже принятый результат без возможности его изменить; если отмена — поздняя загрузка не может завершить старый ответ. Фото записывается до ответа, лишние файлы конкурирующих запросов удаляются сразу, а после сбоев очистки — по журналу.

## Время и восстановление

Новые попытки имеют timing_version=2. Старт создаёт подготовку без активного таймера. После загрузки, декодирования и показа фото, при готовом поле клиент регистрирует начало задачи через /ready. Первый ready_id сохраняется сервером; повтор не меняет его. Декоративные изображения не задерживают начало.

Нажатие кнопки или Enter после проверки непустого ответа синхронно фиксирует интервал до любого await. Неизменяемый ответ с фото и временем остаётся в памяти и отправляется одним multipart-запросом. Копия в IndexedDB сохраняется по возможности с ограниченным ожиданием: отказ записи не блокирует сеть. Фото материализуется, сжимается и хранится отдельно; изменение текста не переписывает байты изображения. В sessionStorage дублируются только небольшие текстовые метаданные, без фото. Передача файла, ответ сервера и подготовка следующего условия не входят в результат. Выбор фото входит. После сбоя или перезагрузки замороженный черновик повторяется с тем же request_id и временем. Перед повтором неизвестный результат проверяется на сервере. При переходе к редактированию сервер отменяет старый запрос; отсчёт возобновляется с накопленного значения, техническое ожидание исключается. Для перезагрузки отдельно сохраняются накопленное время и момент возобновления. Недоступное фото явно требует повторного прикрепления или выбора отправки без него. Принятый запрос сравнивается по тексту, задаче, позиции, ready_id, длительности и SHA-256 фотографии. Конфликт не перезаписывает ответ.

Сумма duration_ms — общее время; среднее и экстремумы вычисляются из исходных миллисекунд. Округление до десятых происходит только при выводе и переносит 59,95 секунды в следующую минуту. Работающий интервал использует performance.now и настенные часы для браузеров, приостанавливающих монотонные часы при блокировке. При обновлении используется сохранённый локальный старт или серверная отметка с поправкой часов. Обновление/фон не ставят активную задачу на паузу.

Сервер хранит начало, зафиксированный конец, длительность и время приёма; проверяет допустимость интервала и неизменность повторов. Он не может доказать момент фактического показа или клика: это хронометраж учебного тренажёра, а не античит. Ручной перевод часов вперёд может увеличить текущий интервал; назад — не уменьшает монотонный интервал. Утрата данных браузера удаляет неотправленный черновик/фото, но не принятый прогресс. Старые незавершённые попытки timing_version=1 завершаются по прежним правилам, без сброса их времени.

## Сроки и очистка

Комнаты и незавершённые попытки доступны 48 часов. Для завершённой попытки result_expires_at = finished_at + 72 часа, где finished_at — серверная фиксация последнего принятого ответа. Время ожидания приёма не входит в результат решения. После закрытия комнаты условия и решения выдаются через защищённые маршруты попытки, с её ключом либо ключом преподавателя. Каждая фотография решения связана с конкретным ответом; правильные ответы до завершения не выдаются.

Миграция 0001 только добавляет поля/индекс/таблицу, заполняет сроки уже готовых отчётов и продлевает журнал их файлов. Старые данные не пересоздаются. COALESCE учитывает старый worker, завершивший попытку между миграцией и обновлением кода.

Очистка сначала удаляет истёкшие ответы/попытки и атомарно помечает ненужные файлы deleting. Живые ссылки комнаты или любого сохраняемого отчёта запрещают удаление общих условий. Только затем удаляются R2-объекты и журнал; сбой R2 оставляет deleting для повтора. Ключи каждой загрузки уникальны, поэтому старое удаление не затрагивает повторную загрузку. Случайный id и хеши доступа остаются в минимальной таблице expired_attempts без ответов и фото: это позволяет корректно показать «Срок хранения результата истёк» даже после очистки. Для этих технических tombstone-записей отдельный срок удаления пока не установлен.

## Проверка файлов и лимиты

JPEG, PNG, WebP: сервер сверяет MIME, расширение и бинарную сигнатуру. SVG, PDF, HEIC отвергаются. Ограничения: 25 задач, 3 МиБ/файл, 18 МиБ/комнату, 200 символов/ответ, 100/название, 120 попыток/комнату. Поток multipart ограничен 19 МиБ с учётом служебных данных. Лимиты D1: 5 созданий/час/IP, 120 стартов/час/IP, 900 API-запросов/минуту/IP и 100 созданий/сутки на весь сервис. Неуспешные создания также учитываются. IP хранится только в виде суточного хеша для ограничений. Нет CAPTCHA и распределённой защиты от массового злоупотребления; для публичного масштабирования потребуются дополнительные ограничения хостинга.

## Строгое сравнение

`trim`, нижний регистр, U+2212 → ASCII `-`. Только целиком десятичная числовая запись допускает точку/запятую, ведущие нули и незначащие конечные нули. Обработка строковая, без потери точности больших целых. Внутренние пробелы, дроби, выражения и пунктуация нечисловых ответов не упрощаются. OCR и символьной математики нет.

## Восстановление камеры

Состояния контроллера: loading, preparing, editing, sending, failed, recovering, transition, finished. Обработка заменяемого фото имеет номер поколения; запоздалое завершение не восстанавливает удалённый файл. Ошибки локального кэша содержат в диагностике только этап и имя исключения. Запрос отправки ограничен 60 секундами. Декодирование/перекодирование изображения ограничено по времени.

Vinext проверяет любой multipart POST до API как возможную серверную форму. Общий предел установлен 20 МиБ, а API сохраняет более строгие потоковые лимиты: решение 3 МиБ + 16 КиБ полей, комната 18 МиБ + поля. Интеграционный тест загружает решение больше прежнего общего порога 1 МиБ. Миграция 0002 только добавляет таблицу отменённых запросов; существующие комнаты, ответы и изображения не меняются.

Черновики объединяются в последнюю версию за 250 мс: нет синхронной записи при каждом символе. Отправка и pagehide немедленно сохраняют только небольшие метаданные; бинарное фото остаётся в IndexedDB. Серверная отправка не ожидает завершения этой очереди. Замороженное время записывается до любого сетевого ожидания. При недоступном кэше отправляется файл из памяти; при его утрате интерфейс просит повторное прикрепление, но сначала проверяет уже принятый сервером ответ.

Загрузка и декодирование ограничены двумя одновременными фотографиями. Решение удерживает текущее и два следующих условия; отчёт загружает только фотографии вблизи видимой области. Владельцы освобождают объектные URL при уходе, замене и удалении. Тайм-аут охватывает и fetch, и decode; зависший декодер не остаётся в кэше. Подготовка больших файлов последовательная, с отдельным ограничением времени и отменой устаревшей операции.

Контроллер проходит loading → preparing → editing → sending → transition/finished. Ошибка переводит в failed; проверка или отмена неопределённой отправки — recovering. Один экземпляр живёт только для одной позиции, поэтому поздняя подготовка фото не меняет следующую задачу. Таймер не обновляет дерево маршрута или фотографии.
