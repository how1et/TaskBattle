# Данные и сроки

Постоянные данные находятся в D1, файлы — в закрытом R2. IndexedDB содержит только необязательный локальный черновик. Схема описана в `db/schema.ts`; приложение выполняет подготовленные SQL-запросы через `lib/server/context.ts`.

| Таблица           | Назначение и инварианты                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| rooms             | Уникальный request_id создания, SHA-256 секрета преподавателя, название и срок created_at + 14 дней.                                                                                |
| tasks             | room_id, исходный ordinal начиная с 1, правильный ответ, ключ и MIME условия. Пара (room_id, ordinal) уникальна.                                                                    |
| attempts          | Отдельный секрет (в базе только хеш), неизменяемый order_json с ID задач, position начиная с 0, ready_id, отметки, версия времени и срок результата.                                |
| answers           | Задача и позиция попытки, текст/оценка, request_id, длительность, необязательные ключ/MIME/SHA-256 фотографии решения. Уникальны (attempt_id, position) и (attempt_id, request_id). |
| blobs             | Журнал файлов, срок и состояние live/deleting. Ссылки действующих комнат и отчётов запрещают удаление.                                                                              |
| cancelled_answers | Запрещает позднее завершение запроса, отменённого перед редактированием ответа. Удаляется с попыткой.                                                                               |
| expired_attempts  | Минимальные ID, хеши доступа и причина истечения для корректного ответа 410. Без ответов и фотографий; отдельного срока удаления пока нет.                                          |
| rate_limits       | Счётчики запросов и срок окна. IP представлен суточным хешем.                                                                                                                       |

Новая попытка получает задачи из `ORDER BY ordinal, id`. Порядок выбранного FileList сохраняется при последовательной обработке и записи. Нумерованный предпросмотр соответствует ordinal. Уже начатая попытка использует свой сохранённый order_json, включая старые перемешанные последовательности. Ответ всегда связан с task_id; отчёт сортируется по исходному ordinal.

`answered_at = started_at + duration_ms` обозначает логический конец решения без технического ожидания. `received_at` — фактический серверный приём. Серверный `finished_at` задаёт начало 72 часов хранения готового отчёта. Каждая попытка получает неизменяемый deadline_at = started_at + 24 часа. Она может продолжаться после закрытия комнаты. Автозавершение записывает finished_at = deadline_at, даже если обработчик вызван позже. Общие условия сохраняются, пока нужны хотя бы одному доступному отчёту.

## Миграции

1. `0000` создаёт исходную схему, включая ordinal и уникальные индексы.
2. `0001` добавляет срок отчётов, активное время, фотографии решений и записи истечения; переносит сроки старых результатов без удаления.
3. `0002` добавляет отменённые отправки для безопасного редактирования после неопределённого результата запроса.
4. `0003` — сгенерированная добавочная миграция: дедлайн, причина, ID завершения, незавершённый интервал и признак неполного времени; индекс (finished_at, deadline_at).
5. `0004` — отдельное заполнение новых полей: сохранённое начало + 24 часа; законченные попытки получают completed. Только ещё доступные комнаты продлеваются до created_at + 14 дней. Истёкшие не открываются. Старые клиентские ready до этого выпуска могли уточнять started_at; для таких записей используется уже сохранённое начало.

Для порядка задач новая миграция не нужна: исходный ordinal уже сохранён во всех комнатах этой схемы. Ни комнаты, ни ответы, ни старые последовательности не переписываются. Применяйте SQL по порядку и только один раз; применённые файлы не редактируйте.
