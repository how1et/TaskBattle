# Данные и сроки

Постоянные данные находятся в D1, файлы — в закрытом R2. IndexedDB содержит только необязательный локальный черновик. Схема описана в `db/schema.ts`; приложение выполняет подготовленные SQL-запросы через `lib/server/context.ts`.

| Таблица           | Назначение и инварианты                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| rooms             | Уникальный request_id создания, SHA-256 секрета преподавателя, название и срок created_at + 14 дней.                                                                                |
| tasks             | room_id, исходный ordinal начиная с 1, правильный ответ, ключ и MIME условия. Пара (room_id, ordinal) уникальна.                                                                    |
| attempts          | Отдельный секрет (в базе только хеш), неизменяемый order_json с ID задач, position начиная с 0, ready_id, отметки, версия времени и срок результата.                                |
| answers           | Задача и позиция попытки, текст/оценка, request_id, длительность, необязательные ключ/MIME/SHA-256 фотографии решения. Уникальны (attempt_id, position) и (attempt_id, request_id). |
| blobs             | Журнал файлов, срок и состояние live/deleting. Ссылки действующих комнат и отчётов запрещают удаление.                                                                              |
| cancelled_answers | Запрещает позднее завершение запроса, отменённого перед редактированием ответа. Удаляется с попыткой.                                                                               |
| expired_attempts  | Минимальные ID, хеши доступа и причина истечения для корректного ответа 410. Без ответов и фотографий; отдельного срока удаления пока нет.                                          |
| rate_limits       | Счётчики запросов и срок окна. IP представлен суточным хешем.                                                                                                                       |

Новая попытка получает задачи из `ORDER BY ordinal, id`. Порядок выбранного FileList сохраняется при последовательной обработке и записи. Нумерованный предпросмотр соответствует ordinal. Уже начатая попытка использует свой сохранённый order_json, включая старые перемешанные последовательности. Ответ всегда связан с task_id; отчёт сортируется по исходному ordinal.

`answered_at = started_at + duration_ms` обозначает логический конец решения без технического ожидания. `received_at` — фактический серверный приём. Серверный `finished_at` задаёт начало 28 суток хранения готового отчёта. Каждая попытка получает неизменяемый deadline_at = started_at + 24 часа. Она может продолжаться после закрытия комнаты. Автозавершение записывает finished_at = deadline_at, даже если обработчик вызван позже. Общие условия сохраняются, пока нужны хотя бы одному доступному отчёту.

В текущем интерфейсе порядок отображения — teacher ordinal, cursor отделён от числа принятых ответов. timing_version=3 использует attempt_intervals, attempt_operations и редактируемые answers.revision; room.amc_year и task.topic необязательны. Предыдущие описания position/answered_at относятся к legacy. Полная актуальная модель: [NAVIGATION.md](NAVIGATION.md).

## Политика 14 / 28 суток

Срок комнаты равен `created_at + 14 × 24 часа`, результата — `finished_at + 28 × 24 часа`. Полное, ручное и автоматическое завершение подчиняются одному сроку результата. Для автоматического завершения `finished_at` равен исходному `deadline_at`, даже если фоновое задание пришло позже. Открытие ссылки, обновление страницы и экспорт не меняют эти даты.

Переход применяется только к данным, доступным на один сохранённый сервером момент обновления политики. Ещё доступные комнаты и результаты получают сроки от своих исходных дат; повтор обработки не начинает срок заново. Ранее истёкшие и удалённые записи не восстанавливаются. Это относится и к запоздавшей очереди автозавершения: попытка, чей результат уже истёк по прежним правилам к моменту перехода, не открывается повторно.

До конца срока результата сохраняются ответы и их статусы, интервалы времени, условия и правильные ответы, фотографии решений, темы и год AMC. Истечение комнаты запрещает новые старты, но не обрывает начатую попытку в пределах её 24 часов и не закрывает доступные отчёты ученика и преподавателя. Общие фотографии удаляются лишь после освобождения всех ссылок от комнаты, попыток и сохраняемых результатов. Экспортированные Google-листы не удаляются при очистке платформы.

## Миграции

1. `0000` создаёт исходную схему, включая ordinal и уникальные индексы.
2. `0001` добавляет срок отчётов, активное время, фотографии решений и записи истечения; переносит сроки старых результатов без удаления.
3. `0002` добавляет отменённые отправки для безопасного редактирования после неопределённого результата запроса.
4. `0003` — сгенерированная добавочная миграция: дедлайн, причина, ID завершения, незавершённый интервал и признак неполного времени; индекс (finished_at, deadline_at).
5. `0004` — отдельное заполнение новых полей: сохранённое начало + 24 часа; законченные попытки получают completed. Только ещё доступные комнаты продлеваются до created_at + 14 дней. Истёкшие не открываются. Старые клиентские ready до этого выпуска могли уточнять started_at; для таких записей используется уже сохранённое начало.

Для порядка задач новая миграция не нужна: исходный ordinal уже сохранён во всех комнатах этой схемы. Ни комнаты, ни ответы, ни старые последовательности не переписываются. Применяйте SQL по порядку и только один раз; применённые файлы не редактируйте.

6. `0005` — добавочные поля метаданных и таблицы интервалов, журнала операций и экспортов Google. Готовые старые отчёты не пересчитываются.
7. `0009_result_retention` — добавляет таблицу `retention_policy` и nullable-поле `attempts.result_ttl_ms`. SQL изменяет только схему. Новый backend один раз сохраняет `retention_policy.applied_at` для ключа `results-28-days`; обработка существующих записей использует этот неизменный момент. `NULL` отмечает ещё не классифицированные старые попытки. Адресное чтение применяет политику к нужной записи, очистка обрабатывает очередь пакетами до 500. Доступный старый результат получает 28 суток от исходного завершения; уже истёкший сохраняет прежнюю закрытую границу.
