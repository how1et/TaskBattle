# Экспорт в один XLSX на Яндекс Диске

Статус: реализация и регрессионные тесты готовы; подключение к реальному Диску и живой экспорт ещё не выполнены.

В Yandex-профиле Google не используется. Преподаватель выбирает AMC8 или свободную форму, сервер добавляет лист в **тот же XLSX**, затем проверяет полный SHA256 скачанного результата. Это согласованная альтернатива, а не API редактирования нативных Яндекс Таблиц. У API Диска документированы [загрузка](https://yandex.com/dev/disk-api/doc/en/reference/upload) и [скачивание](https://yandex.com/dev/disk-api/doc/en/reference/content) файлов; публичный API добавления листов нативного документа не подтверждён.

## Первое подключение

1. Владелец подтверждает точный путь нового файла (предложение: `disk:/Результаты TASKBATTLE.xlsx`). Не выбирать существующий чужой документ: сервер откажется его заменять. Папка должна уже существовать.
2. Зарегистрировать серверное приложение в [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-client) с необходимыми правами чтения и записи Диска. Владелец сам входит и подтверждает доступ. Пароли и токены не передавать в чат или GitHub.
3. Получить OAuth-токен по официальному flow и сохранить `YANDEX_DISK_TOKEN` в payload серверного Lockbox. Секрет доступен только сервисному аккаунту VM. Никаких токенов в клиентском коде или URL TaskBattle.
4. Указать `YANDEX_DISK_PATH` в `/etc/taskbattle/runtime.env`; перезапустить приложение после изменения секрета. В интерфейсе только название файла и ссылка на него, никаких OAuth-данных.
5. На опубликованном сайте проверить два разных шаблона, повтор одного экспорта и два параллельных экспорта; вручную открыть файл в Яндекс Диске, проверить листы, значения и числовое форматирование.

Текущая конфигурация использует долгоживущий серверный OAuth-токен. При отзыве или истечении владелец обновляет подключение через Lockbox; автоматическая ротация refresh-токена пока не подключена. [Официальный механизм обновления](https://yandex.ru/dev/id/doc/ru/tokens/refresh-client) требует сохранения новой пары токенов, а не только повторного использования старого refresh-токена. Реальный scope и срок токена необходимо проверить при подключении.

## Гарантии и ограничения

- Результат связан с попыткой и шаблоном в `yandex_export_jobs`. Экспортный журнал живёт независимо от очистки попыток через 72 часа. Готовый XLSX не удаляется.
- Сохраняются исходные номера, темы, AMC-год, даты с часовым поясом, способ завершения, десятые секунды. Время — число в секундах. Пользовательский текст — строка, не формула.
- Все записи в одну книгу сериализованы. Перед отправкой фиксируются байты, SHA256, marker и статус операции в SQLite. Потеря подтверждения не вызывает слепой повтор PUT: сначала сверяются удалённый файл и marker.
- Если исход загрузки не удалось установить, запись в книгу блокируется до сверки. Преподаватель может повторить проверку. При длительном сбое оператор сверяет `status`, `payload_hash`, `baseline_hash` и реальный файл, не удаляет журнал и не сбрасывает статус вслепую.
- Диск не даёт проверенного атомарного compare-and-swap по версии. Поэтому нужен отдельный файл TaskBattle, который не редактируют одновременно в редакторе. Проверка хеша перед PUT уменьшает риск, но не устраняет гонку с внешним редактором.
- Не более 20 МиБ сжатого XLSX и 80 МиБ распакованных данных. Книга не растёт бесконечно; при достижении лимита экспорт останавливается без перезаписи. Новый файл согласовывается с владельцем отдельно.
- Неподдерживаемые объекты (диаграммы, рисунки, сводные таблицы, внешние связи, макросы) приводят к отказу вместо потери содержимого. Скрытый служебный лист `_TaskBattle` нельзя удалять.
- Ссылка открывает файл в аккаунте владельца Диска. Она не публикует его для всех и не требует входа ученика.

Тесты используют имитацию официального транспорта, проверяют реальные XLSX через ExcelJS, но не являются подтверждением живого экспорта.
