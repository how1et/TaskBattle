# Внесение изменений

Используйте Node.js 24 и npm с существующим package-lock.json. Обсудите крупные изменения до добавления новых сервисов или зависимостей. Для небольших исправлений создавайте ветку и PR с конкретной причиной, результатом и проверками.

Перед PR выполните `npm run format`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. GitHub Actions повторяет проверки при PR и обновлении main. Форматирование охватывает код приложения, тесты, схему и документацию; сгенерированные миграции и предоставленные UI-компоненты сохраняются как есть.

Для изменений прохождения проверяйте независимые попытки, обновление страницы, медленную сеть, повтор после потерянного подтверждения и чистое состояние следующей задачи. Не называйте подстановку файла проверкой настоящей камеры. Используйте только искусственные фотографии вне репозитория.

Изменения схемы добавляйте новой миграцией; не редактируйте применённые SQL-файлы и не переписывайте действующие order_json. Не меняйте сроки хранения или способ проверки ответов без явного требования. Новую миграцию проверяйте на существующих данных.

Секреты, URL попыток с ключами, пользовательские фотографии и базы не включайте в PR и диагностику. Сообщайте об обнаруженном опубликованном секрете без его значения; владелец должен его отозвать.

Лицензия исходного кода пока не выбрана владельцем. Этот файл не предоставляет лицензионных прав. Отдельные изображения и шрифты описаны в docs/ASSETS.md.
