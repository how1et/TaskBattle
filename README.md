# TaskBattle

Веб-тренажёр задач по фотографиям без регистрации. Преподаватель создаёт комнату на 48 часов, ученик решает задачи в порядке загрузки преподавателем на время. Постоянное хранение — Cloudflare D1 и закрытый R2, сервер — Cloudflare Worker, интерфейс — React 19 / Vinext / TypeScript.

## Преподавателю

1. На главной загрузите 1–25 фотографий (JPEG, PNG или WebP) и введите короткий правильный ответ к каждой. Название необязательно.
2. Нажмите «Создать комнату» и отправьте ученику ссылку из первого поля.
3. Сохраните отдельную секретную ссылку преподавателя. Не отправляйте её ученику. По ней доступны попытки и отчёты до указанной даты и времени.

При обрыве связи создание автоматически проверяется на сервере и при необходимости повторяется один раз с прежним идентификатором. Если связь не восстановилась, фотографии и ответы остаются в форме: нажмите «Повторить создание», не обновляя страницу. Браузер предупреждает об уходе с заполненной формы. Указатель незавершённого создания хранится в sessionStorage: после обновления можно восстановить уже сохранённую сервером комнату, но фотографии ещё не отправленной формы придётся выбрать заново.

Ученик открывает ссылку, нажимает «Старт» и отвечает на каждую задачу. Фото решения можно выбрать из галереи или снять камерой; текстовый ответ обязателен. Enter отправляет ответ. Нажатие на фотографию увеличивает её. При сбое используйте «Повторить отправку». Чтобы изменить ответ, нажмите «Изменить ответ» или выберите новое фото. «Отправить без фото» доступно только как явное действие. Можно обновлять страницу и возвращаться в ту же попытку по её полной ссылке. После завершения доступна новая независимая попытка.

## Локальный запуск

Требуется Node.js 22.13+ (для тестов с TypeScript без компиляции рекомендуется Node.js 24) и npm. Платные API и секреты не нужны.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_flaky_major_mapleleaf.sql
npm run dev
```

Откройте адрес, напечатанный сервером (обычно http://127.0.0.1:5173). Данные разработки остаются в игнорируемой `.wrangler/state`. К новой базе примените также `drizzle/0001_adorable_dormammu.sql` и `drizzle/0002_open_gorilla_man.sql` той же командой. К существующей базе применяется только новая миграция, один раз. Последующие миграции из `drizzle/` применяются по порядку. `npm start` запускает собранную production-версию локально. На Windows при проблеме npm.cmd вызывайте `node "C:/Program Files/nodejs/node_modules/npm/bin/npm-cli.js"` с теми же аргументами.

## Проверки

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
node scripts/integration.mjs
node scripts/check-expiry.mjs
```

Для интеграционных проверок должен работать локальный сервер. `scripts/integration.mjs` создаёт комнату и два независимых клиентских контекста, проверяет отчёт, двойные запросы, потерю HTTP-ответа через тестовый proxy, доступ и MIME. По умолчанию используются встроенные синтетические PNG. Можно указать `TEST_PHOTO_DIR` с task-1.png, task-2.png, task-3.png. Для проверки истечения сначала задайте `TEST_STATE_FILE=../integration-state.json`; этот файл содержит только временные тестовые ссылки и должен оставаться вне Git. `check-expiry.mjs` разрешает только loopback и меняет только тестовую локальную базу. Он проверяет независимые сроки комнаты/отчёта, закрытый доступ к фото и очистку. `tests/lifecycle.test.mjs` проверяет миграцию и управляемое время, в том числе несколько отчётов с общими файлами и сбой удаления R2.

Для браузерной проверки задержек: `node scripts/latency-proxy.mjs`, откройте http://127.0.0.1:5174. Параметры в локальном `../latency.json`: `photoMs`, `answerMs`, `readyMs`, `dropAnswers` (число ближайших отказов до записи). Этот прокси не входит в приложение и не публикуется как маршрут.

Черновик — необязательная страховка: фото хранится отдельно от текста в IndexedDB, предпросмотр использует объектный URL. Ошибка локального сохранения не запрещает отправку файла из памяти. При недоступном хранилище не закрывайте вкладку до отправки; после утраты файла потребуется прикрепить его заново. Base64 в localStorage/sessionStorage не используется.

## Ограничения MVP

- 25 задач; 3 МиБ на файл; 18 МиБ на комнату; 120 попыток на комнату; 200 символов на ответ.
- 5 новых созданий в час на IP и 100 в сутки на сервис. Неудачные новые создания учитываются; восстановление уже созданной комнаты квоту не расходует. Для учебного класса используется общий лимит до 120 новых попыток в час на IP.
- Комната открыта 48 часов. Готовый отчёт хранится 72 часа после завершения, независимо от закрытия комнаты.
- Таймер запускается после показа и декодирования условия. Нажатие «Ответить» фиксирует время до передачи данных. Общее время — сумма интервалов задач; сеть и подготовка исключены. Выбор фото, фон и блокировка экрана учитываются. В интерфейсе — десятые секунды, в базе — миллисекунды.
- Условия и решения проходят одинаковую подготовку; фото решения — одно на задачу. Исходник до 30 МиБ и 60 мегапикселей. Браузер сохраняет ориентацию, уменьшает длинную сторону до 2560 px и сжимает в JPEG до 3 МиБ. JPEG/PNG/WebP; HEIC/HEIF нужно заранее преобразовать в JPEG.
- Строгое сравнение коротких ответов: пробелы по краям, регистр, десятичные записи и знак минуса нормализуются; выражения не вычисляются. OCR, доказательства равенства, античит, учётные записи и восстановление утраченной секретной ссылки отсутствуют.
- Для продолжения после закрытия браузера сохраните полную ссылку попытки. Очистка истории/данных браузера может удалить локальный неотправленный черновик, но не принятые сервером ответы.
- Автоматическая физическая очистка требует активного GitHub Actions workflow и переменной TASKBATTLE_URL. Задержка планировщика не продлевает доступ: сервер проверяет оба срока самостоятельно. GitHub может отключить расписание неактивного публичного репозитория — проверяйте Actions.
- Проверки размеров планшета выполняются в Chromium. Реальный iPad Safari и Android Chrome требуют отдельной проверки на устройствах; интерфейс использует стандартные touch/viewport API и поля не меньше 16 px.
- Фото проверяются по формату/MIME/сигнатуре; размеры проверяются, EXIF-ориентация учитывается браузером. И условия, и решения в интерфейсе перекодируются в JPEG; прямой API также принимает JPEG/PNG/WebP. Антивирусного анализа нет. Загружайте только фотографии, которыми можно делиться по ссылке.

Ни база, ни фотографии, ни секретные ссылки/токены в репозиторий не включаются. Никакие платные услуги кодом не подключаются.

Новые попытки получают задачи в порядке нумерованного предпросмотра. Уже начатые попытки сохраняют прежнюю последовательность и привязку ответов.

Лицензия исходного кода владельцем не выбрана. Условия использования отдельных изображений и шрифтов перечислены в docs/ASSETS.md.
